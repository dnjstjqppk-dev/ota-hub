> 의존 TG-09·TG-15.

## 1. 기판 결정: FTS5 코어 + 백엔드 인터페이스

- v1은 **SQLite FTS5**(D1 내장) + `SearchBackend` 인터페이스. Typesense·ES는
  매니지드 선정 후 사용자 단계에서 인터페이스 뒤에 붙는다 (TG-13 OTLP와 동일
  분리 — 코드가 바이너리 없이 로컬·CI에서 전부 검증됨).
- 근거: 사용자 머신 바이너리 추가 금지(TG-04 규율), 격리 E2E 결정성,
  10만 행대에서는 FTS5+인덱스로 p95를 맞출 수 있음(§4-A4에서 실측 판정).
- FTS5 인덱스: 신규 마이그레이션 `0049` (가상 테이블 + 동기화 트리거 —
  INSERT/UPDATE/DELETE 시 자동 반영, 배치는 없음).

## 2. 범위 (v1)

1. `GET /api/v1/search` 통합 엔드포인트: `q`·`domain`·패싯(도시·가격대·평점)·
   지리(bbox)·날짜 가용성·정렬·페이지. 기존 도메인별 목록 API는 그대로 유지
   (호환 — 프론트 이주 없음).
2. FTS5 랭크(`bm25`) + 한국어 토큰 한계 명시 ( trigram 미사용 — CJK는 LIKE
   폴백 병행, §3).
3. 핫 캐시: isolate LRU(상위 쿼리) + Redis ephemeral(설정 시) — 키는 정규화
   쿼리 해시, TTL 60초, 상품 변경 시 태그 무효화(TG-15 purge와 합류).
4. 검색 로그 파이프라인: `analytics_events`에 `search` 타입 확장(쿼리·필터·
   결과수·지연) + 어드민 인기 검색어 조회 (`/api/v1/admin/search/terms`).
5. PG 스키마 이식 (FTS5 가상 테이블은 PG `tsvector` 컬럼+인덱스로 포팅 —
   porter 확장이 필요하면 별도 커밋 없이 동일 배치에 포함) + 체크리스트
   0단계에 0049 주의.

## 3. 비목표 (명시)

- Typesense/ES/Vespa 실연동 없음 — 인터페이스 + FTS5 구현까지 (수신기는
  매니지드 선정 후).
- 형태소 분석기 없음 — 한국어 복합명사는 LIKE 폴백으로 커버, 정밀도 한계는
  문서에 명시 (ES 전환 시 nori로 해소).
- 자동완성(suggest) 없음 — 후속 (인기 검색어 조회로 대체).
- 기존 도메인별 API 제거·프론트 이주 없음 — 통합 엔드포인트 추가만.

## 4. 수용기준 → 작업 → 증거

| # | 수용기준 | 작업 | 증거 |
|---|---|---|---|
| A1 | 패싯·지리·가용성 통합 쿼리 (백로그 수용) | search-service + /search | E2E tg16a (도시+가격+평점+bbox 조합). "가용성"은 bookable 주석(판매 가능 여부)으로 확정 — 일자별 매진 투영은 후속 (구현 중 스코프 확정). |

## 5. 레드드릴

1. FTS 테이블 DROP 후 검색 → LIKE 폴백 200 + `fallback: true` (표적).
2. 캐시 오염(상품 비활성 후) → purge 후 미노출 (E2E tg16b 내 단언).
3. 특수문자·초과 길이 쿼리 → 400 + 로그 미적재 (유닛).

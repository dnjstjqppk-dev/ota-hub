# Trip.com급 OTA 갭 분석 — 2026-11-14

> 기준: `main@4b88a96`. 실측 기반(ARCHITECTURE.md·wrangler.jsonc·패키지·D1 공식 한도).
> 코드 구현분은 [개발 백로그](TRIP_GRADE_BACKLOG.md) TG-01~TG-21로 분리.
> 선행: [오픈 준비점검](OPEN_READINESS_20261109.md), [전수 감사](FULL_AUDIT_20261109.md).

## 0. 결론

- 개발 언어 변경 불필요. TypeScript(서빙) + Go(보조) + Vue/Nuxt + Flutter(예정)는
  Trip.com급에서도 통하는 조합이다. 문제는 언어가 아니라 D1 단일 DB·공급망 부재·
  비동기 인프라 부재다.
- 가장 급한 건 D1 탈출 계획. 현 DB는 DB당 10GB 하드캡·단일 라이터라 OTA 주문·재고
  단일 진실을 담을 그릇이 아니다.
- Trip.com의 본질은 GDS/NDC·호텔 어그리게이터·IATA·글로벌 PG 같은 외부 연결망이다.
  개발이 아니라 제휴·라이선스·보증금의 영역이 병목이다.
- 모바일 앱 없이는 OTA가 아니다. 예약 주전장이 앱이라 Flutter는 "대비"가 아니라 필수다.
- 나머지는 매출 단계별로 지르면 된다(§14 로드맵).

## 1. 현재 스택 (실측)

- 서빙: Cloudflare Workers 단일 모놀리스(`worker/src` 약 10,349줄·14개 라우트)
  + D1 1개 + R2 + 5분 크론. KV·Queues·Durable Objects 없음.
- 보조: Go 1.23 약 5,506줄 — 배포 배선에 없고 테스트만 유지. 같은 도메인을
  두 언어로 이중 구현한 상태.
- 웹: 사용자 Nuxt 4 SSG + Vue 3.5, 어드민·파트너 Vite 5 SPA. 모바일 디렉터리 없음.
- DB: D1 마이그레이션 44개. 유닛 134·E2E 188, CI는 단일 gate+deploy.
- 외부: 결제 DISABLED(Toss 예정), 메일·Sentry 미설정, 카탈로그 목시드.
- 참고: TECH_STACK_AUDIT.md는旧 설계안(Go 서빙·PostgreSQL) 기술이라 현실과 어긋난다.

## 2. 언어·런타임: 바꾸지 말고 이중 구현을 정리 (→ TG-01)

- 유지. TS(엣지·BFF·프론트)와 Go(무거운 서비스)의 역할 분담이 자연스럽다.
- 변경. 예약·정산 로직의 TS/Go 이중 보유를 해소. 원칙: 서빙 진실은 TS 워커,
  Go는 워커에서 못 하는 것(장시간 집계·공급사 대량 동기화·정산 배치)만.
- 채택. 데이터/ML용 Python은 웨어하우스·추천 시점에. Rust 등은 불필요.

## 3. 컴퓨트·호스팅: Workers 유지, 상태ful 코어는 분리

- 유지. Workers + R2 + 엣지 캐시는 API 게이트웨이·BFF·웹 서빙으로 오래 간다.
- 채택 순서. ① Cloudflare Queues + 잡 체계(→ TG-11) ② 컨테이너 실행처 1곳
  (Cloud Run/ECS/GKE 택1, Go 배치·동기화 데몬용) ③ 멀티리전(→ TG-20).
- 기준. "워커 CPU·실행시간 안에 안 끝나는 작업"이 분리 시점. 이른 K8s는 운영비만 든다.

## 4. 데이터베이스: 최대 과제 (→ TG-07·TG-09·TG-20)

- 현실. D1은 "수많은 작은 DB 수평 확장"용이지 OTA 단일 진실용이 아니다.
  10GB 하드캡·단일 라이터·호출당 쿼리 1,000개가 천장이다.
- 변경 2단계. 1단계: Postgres 호환 매니지드 RDBMS로 주문·결제·정산·재고 이전 +
  읽기 복제본, D1은 엣지 잡데이터로 격하. 2단계: 샤딩/분산(Citus·TiDB·OceanBase 계열).
  Trip.com의 MySQL→OceanBase 이전이 이 단계의 답이다.
- 채택. 커넥션 풀러(서버리스→RDBMS 필수), 시계열(요금·검색 로그), PITR·복구 드릴.

## 5. 캐시·비동기·잡: 현재 0점 구역 (→ TG-10·TG-11)

- 채택. Redis(세션·레이트리밋·재고 홀딩·멱등키) → 메시지 큐(Kafka/Redpanda,
  초기엔 Cloudflare Queues) → 잡 큐+재시도·데드레터(5분 크론 대체).
- 이유. "결제 승인→공급사 발권→바우처"는 비동기·재시도·보상 트랜잭션 saga다.
  실행 기반 없이 E2E만으로는 반쪽이다.

## 6. 검색: SQL 검색은 상품 10만 개가 한계 (→ TG-16)

- 채택. Typesense/Meilisearch → Elasticsearch/OpenSearch/Vespa. 패싯·정렬·지리반경·
  가용성 조인이 한 쿼리에 들어간다. 핫 검색 캐시·검색 로그 파이프라인 세트.
- 호텔 검색 API 업계는 일 수십억 요청의 세계다. 정적 SEO 스냅샷과 실검색은 분리.

## 7. 공급망 커넥티비티: 코드가 아니라 사업개발 (→ TG-14·TG-18)

- 채택. 호텔 어그리게이터 2곳 이상(Hotelbeds·EPS Rapid·RateHawk·WebBeds 중),
  항공 GDS + NDC 직연동 + LCC 직API. 매핑 DB·요금 캐시·정산 대사 파이프라인.
- 변경. 시뮬레이터는 개발용 격리, 운영 어댑터 인터페이스(타임아웃·서킷브레이커·
  폴백·재시도 예산) 고정. 공급사 1곳당 전담 커넥터 + 샌드박스 E2E.
- 순서. 파일럿(제휴 아웃링크·수동 발권) → 1개 어그리게이터 → GDS. 라이선스·보증금·
  최소 거래량이 따르므로 기술 범위를 넘는다.

## 8. 결제·정산·사기: Toss는 시작 (→ TG-17)

- 채택. 글로벌 PG(Adyen 또는 Stripe) 메인 + Toss 한국 수단 병렬. 3DS·네트워크 토큰·
  현지 간편결제까지 가야 결제 커버리지 완성.
- 채택. 사기 탐지(Riskified/Forter/Sift 또는自社 룰+ML) + 차지백 대응. FDS 없이
  해외 판매는 불가.
- 변경. 정산은 현 원장을 복식부기·마감·세금·다통화 지급으로 확장. PG 토큰화로
  PCI-DSS 범위를 축소하는 게 정석이다.

## 9. 웹 프론트: 스택 유지, 렌더링 전략 격상 (→ TG-15)

- 유지. Nuxt + Vue 3.5 + Tailwind 그대로. React 전환 불필요.
- 채택. SSG 전면 렌더 → ISR/온디맨드 + 엣지 캐시, 이미지 최적화(AVIF·srcset),
  피처플래그, 웹 성능 예산(LCP·INP CI 게이트).

## 10. 모바일: Flutter를 본공정으로 (→ TG-12)

- 채택. Flutter iOS·안드로이드 동시. 푸시·딥링크·크래시 리포팅·스토어 베타 세트.
- 현 REST+SSE 계약을 모바일과 공유하는 설계는 방향이 맞다. API 버전닝·강제
  업데이트 정책만 미리 고정.

## 11. 관측·SRE: Sentry는 10% (→ TG-05·TG-13·TG-04)

- 채택. OpenTelemetry + Grafana/Prometheus + 로그 집계 + 합성 모니터링 + 상태 페이지.
- 채택(프로세스). SLO·온콜·블레임리스 리뷰·게임데이·부하 테스트(k6/Locust).
  현 E2E는 기능만 보고 부하는 안 본다.
- 변경. CI를 빠른 gate / E2E / 배포로 분리(→ TG-06). post-commit 자동 운영배포는
  폐지 수순(→ TG-02, 2026-11-14 사고 참조).

## 12. 데이터·ML: 예약이 쌓이면 (→ TG-03·TG-19·TG-21)

- 채택. 웨어하우스 + ETL + 실험 플랫폼, 그 위 추천·수요 예측·동적 마크업·리뷰 LLM·CS봇.
- 기준. "하루 예약 4자리수"가 데이터팀 신호. 그 전엔 퍼널 이벤트 스키마만 선행.

## 13. 보안·컴플라이언스: 라이선스가 입장권 (외부·조직, 코드 아님)

- PCI-DSS(토큰화 축소), IATA 인증 + BSP(항공 직판 입장권), GDPR·PIPL·각국
  전자상거래법, SOC 2 Type II, 연 1회 모의해킹 + 버그바운티.
- 코드분: 시크릿 관리·키 로테이션 자동화·어드민 4-eyes 승인. 약관 법무 검토는 파일럿 전제.

## 14. CS·조직: 소프트웨어의 절반은 사람 (외부·조직, 코드 아님)

- 티켓·콜센터·챗 다국어 24/7(외주 시작 가능), 긴급 대량 변경 프로세스, 통합 CS 콘솔.
- 최소 플랫폼/공급망/결제/앱/데이터/SRE 6축 전담. 스테이징 환경(→ TG-08)은 코드분.
